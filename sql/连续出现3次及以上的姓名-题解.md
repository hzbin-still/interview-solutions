# 题解：查询连续出现 3 次及以上的姓名

## 📌 题目

有一张 `test_sql_exam` 表，只有两个字段：自增主键 `id` 和姓名 `name`。请写 SQL 找出**连续出现 3 次及以上**的姓名，结果按姓名倒序排列。

```sql
CREATE TABLE `test_sql_exam` (
  `id` int NOT NULL AUTO_INCREMENT,
  `name` varchar(100) DEFAULT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='考试题，测试表';
```

**示例数据：**

| id | name |
|---|---|
| 1 | 张三 |
| 2 | 张三 |
| 3 | 张三 |
| 4 | 李四 |
| 5 | 李四 |
| 6 | 王五 |
| 7 | 张三 |
| 8 | 张三 |
| 9 | 赵六 |
| 10 | 赵六 |
| 11 | 赵六 |
| 12 | 赵六 |

**期望输出：** `赵六`、`张三`

> 张三在 id 7~8 只连续 2 次不算，但 id 1~3 连续 3 次，故入选；李四最多连续 2 次，落选。

---

## ✅ 解法：三次自连接（滑动窗口思想）

### 核心思路

把表想象成一条序列，用**三个指针同时指向相邻的三行**（`id`、`id+1`、`id+2`），检查这三行的姓名是否完全相同。

- 只要存在一段长度 ≥ 3 的连续姓名，其中**必然包含至少一个"三连窗口"**，所以这个判断是充分的；
- 连续 2 次的姓名凑不出三连窗口，自然被排除；
- 一段连续 4 次会产生 2 个满足条件的窗口，所以要用 `DISTINCT` 去重。

### SQL

```sql
SELECT DISTINCT a.name AS name
FROM test_sql_exam a
JOIN test_sql_exam b ON b.id = a.id + 1
JOIN test_sql_exam c ON c.id = b.id + 1
WHERE a.name = b.name
  AND b.name = c.name
ORDER BY name DESC;
```

### 逐句解释

| 语句 | 作用 |
|---|---|
| `test_sql_exam a JOIN test_sql_exam b ON b.id = a.id + 1` | 构造相邻两行 |
| `JOIN test_sql_exam c ON c.id = b.id + 1` | 扩展为相邻三行，得到所有"三连窗口" |
| `WHERE a.name = b.name AND b.name = c.name` | 窗口内姓名全相等 ⇒ 存在连续 3 次 |
| `DISTINCT` | 连续 4 次及以上会命中多个窗口，去重 |
| `ORDER BY name DESC` | 按姓名倒序输出 |

### 示例推演

以 `a` 表为主扫描窗口：

- a=1(张三)：窗口 {1,2,3} = 张三/张三/张三 → ✔ 命中
- a=4(李四)：窗口 {4,5,6} = 李四/李四/王五 → ✘
- a=7(张三)：窗口 {7,8,9} = 张三/张三/赵六 → ✘（前一段已命中，不影响结果）
- a=9(赵六)：窗口 {9,10,11} ✔；a=10：窗口 {10,11,12} ✔ → 两次命中同一人，`DISTINCT` 去重为一条

**输出：**

| name |
|---|
| 赵六 |
| 张三 |

---

## ⏱ 复杂度分析

- 连接基于主键 `id` 的等值偏移（`a.id + 1`），每行最多探测 2 次索引查找，整体约 **O(n)**；
- 主键自带聚簇索引，**无需额外建索引**；
- 结果集小，`DISTINCT` 与排序开销可忽略。

## ⚠️ 局限与面试追问

1. **依赖 id 严格连续无空洞**：如果表删除过数据导致 id 跳号（如 1,2,4,5,7），真正的"按插入顺序连续"可能被漏判。
   - 面试回答话术：*"此写法的前提是自增 id 连续；若可能有空洞，应先 `ROW_NUMBER()` 按 id 排序重新编号再连接，或直接改用双 ROW_NUMBER 差值分组法（间隔与岛屿解法），后者天然不依赖 id 值本身。"*
2. **为什么用 `DISTINCT` 不用 `GROUP BY`**：两者皆可，`GROUP BY a.name` 效果相同，`DISTINCT` 语义更直白。
3. **如果只要"恰好连续 3 次"**：需额外排除前后相邻行同名的情况（窗口两侧加 `NOT EXISTS` 判断），一般题目要求"3 次及以上"，本解法即满足。
4. **扩展为 N 次**：连接 N-1 张自身表的条件太笨重，连续 N≥4 的场景建议直接升级到窗口函数解法，这也是面试官引导你优化的常见方向。
